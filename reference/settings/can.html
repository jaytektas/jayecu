    Can settings¶

    Setting What it does
    OBD-II Enabled
    can.obd_enabled
    Range: Off or On
    Default: On    		 Answer OBD-II diagnostic requests (mode 01 live data, mode 03 stored codes) on the selected bus. This is the standardised scan-tool interface, not the ECU's own protocol — a generic reader plugged into the car talks to this, and it is independent of any custom CAN frames configured elsewhere.
    OBD-II Bus
    can.obd_bus
    Range: one of: CAN1, CAN2
    Default: CAN2    		 Which physical CAN controller answers OBD-II. It defaults to CAN2 so the OBD port can be a separate bus from CAN1, which is typically the tuning/instrument link — a scan tool then cannot see, or interfere with, the traffic on that one.
    Bus Enabled
    can.bus[].enabled
    Range: Off or On
    Default: On    		 Bring this bus up at all. A bus that is wired to nothing sits error-passive; switch it off instead. Applies to each of: CAN1, CAN2.
    Bitrate
    can.bus[].bitrate
    Range: one of: 125 kbit, 250 kbit, 500 kbit, 1 Mbit
    Default: 500 kbit    		 Bit rate for this bus. 500 kbit is OBD-II; CAN sensors are commonly 1 Mbit. Every node on a bus must agree — a mismatch never ACKs, which looks exactly like nothing being connected. Applies to each of: CAN1, CAN2.
    Listen Only
    can.bus[].listen_only
    Range: Off or On
    Default: Off    		 Receive without ever transmitting or ACKing (silent mode). For tapping a bus you do not own — the ECU cannot disturb it. Nothing the ECU sends on this bus will go out, OBD replies included. Applies to each of: CAN1, CAN2.
    Frame Flags
    can.gc_frame[].flags
    Range: 0 to 255
    Default: 0    		 Bit 0 in use, bit 1 transmit (clear = receive), bit 2 extended (29-bit) id, bit 3 PARKED (kept in the tune, not run). A frame with bit 0 clear is a free slot and is skipped entirely.
    Bus
    can.gc_frame[].bus
    Range: one of: CAN1, CAN2
    Default: CAN1    		 Which physical controller carries this frame. Frames on a bus that is switched off (Bus Enabled) do not run.
    CAN ID
    can.gc_frame[].id
    Range: 0 to 536870911
    Default: 0    		 The identifier. 11-bit ids run to 0x7FF; set the extended flag for a 29-bit id, which is a separate address space — 0x100 standard and 0x100 extended are different frames on the same wire.
    Frame Length
    can.gc_frame[].dlc
    Range: 0 to 8
    Default: 8    		 Payload bytes. Transmit sends exactly this many; a field whose bits fall past the end is dropped rather than scribbling outside the frame. Receive decodes only the fields that fit inside the frame that actually arrived: a field whose bits fall past its end is not decoded, so it goes stale rather than reading as zero.
    Transmit Period
    can.gc_frame[].period_ms
    Range: 0 to 65535
    Default: 50
    Units: ms    		 How often a transmit frame goes out, in milliseconds — 50 is 20 Hz, 10 is 100 Hz. Ignored by a receive frame. Deadlines are spread across the period at start-up, so frames sharing a rate trickle instead of arriving as a burst.
    First Field
    can.gc_frame[].first_field
    Range: 0 to 511
    Default: 0    		 Index of this frame's first field in the shared field pool. The studio maintains this; it is not meant to be typed.
    Field Count
    can.gc_frame[].field_count
    Range: 0 to 64
    Default: 0    		 How many fields from First Field belong to this frame. The studio maintains this.
    Frame Name
    can.gc_frame[].name    		 What this frame is for, in your words — "dash gauges", "gear display". Carried so a tune stays readable a year later; the ECU never uses it.

this field carries. On a transmit frame it is read from the bus; on a receive frame the decoded value is written to it. Anything on the bus can be either — a sensor, a derived value, a state word. 65535 is UNSET, which on a receive frame is not a dead field but one a SENSOR reads — point the sensor's CAN Frame and Start Bit at it and the sensor publishes the channel, with its calibration and diagnostics. It cannot be 0: that is a real channel (abs_mode), so a field left alone would publish onto it.
    Start Bit
    can.gc_field[].bit_off
    Range: 0 to 63
    Default: 0    		 Where the field starts, numbered byte*8 + bit with bit 7 the most significant of its byte — byte 0 bit 7 is 7, byte 1 bit 7 is 15, byte 7 bit 0 is 56. This is the numbering DBC files and every CAN tool use, so a field copied from a document or another tool is the same number here. For a big-endian (Motorola) field this is the field's MOST significant bit and the field runs down into the next byte; for little-endian (Intel) it is the LEAST significant bit and the field runs up.
    Bit Length
    can.gc_field[].width
    Range: 1 to 32
    Default: 8    		 How many bits the field occupies. Odd widths are fine — a 1-bit flag, a 12-bit sensor, a 4-bit gear all address the same way.
    Field Flags
    can.gc_field[].flags
    Range: 0 to 255
    Default: 0    		 Bit 0 signed (the slice is two's complement, so a negative value survives rather than clamping to zero), bit 1 little-endian/Intel bit order, bit 2 the No Reading code below is in use.
    No Reading Code
    can.gc_field[].sentinel
    Range: 0 to 4294967295
    Default: 0    		 Receive only, and only when flags bit 2 is set: the RAW code this sender uses to say it has nothing to report — a wideband in free air sends 0x7FFF rather than a lambda. A frame carrying it is ignored for this field, so the value simply stops being refreshed and expires on its Valid For time. That is the difference between "no reading" and a reading of whatever the code happens to decode to, which for a wideband is a plausible and completely wrong mixture.
    Multiplier
    can.gc_field[].scale
    Range: -1000000.000 to 1000000.000
    Default: 1.000    		 Transmit encodes raw = value * Multiplier + Offset; receive decodes value = (raw - Offset) / Multiplier. Stated once in the transmit direction so the two can never disagree. A spec written as "y = x/10 - 101.3" is a Multiplier of 10 and an Offset of 1013.
    Offset
    can.gc_field[].offset
    Range: -1000000.000 to 1000000.000
    Default: 0.000    		 The constant half of the transform — see Multiplier. Where two systems disagree about zero this is what says so: Kelvin against Celsius is an offset of 2731.5 with a multiplier of 10.
    Valid For
    can.gc_field[].ttl_ms
    Range: 0 to 65535
    Default: 500
    Units: ms    		 Receive only: how long a decoded value stays good. If the frame stops arriving the signal expires and everything reading it sees an absent channel rather than a number frozen at whatever it last was. Size it at a few times the sender's period. 0 means never expire, which is almost never what you want.
    If Absent
    can.gc_field[].policy
    Range: one of: Send zero, Hold last, Skip frame
    Default: Send zero    		 Transmit only: what goes in these bits when the signal has nothing to say — the sensor is not fitted, has failed, or nobody holds the role. Send zero writes RAW zero, which through an offset is a visibly broken reading and is the point of it; Hold last leaves the bits alone; Skip frame suppresses the whole frame this cycle, which costs the other fields in it and is the trade you are making when you choose it.
    Priority
    can.gc_field[].priority
    Range: 0 to 255
    Default: 10    		 Receive only: the authority this value is written with. A write is refused only by a STRICTLY higher priority, so two producers at the same number alternate and neither wins — which is why the default is 10 rather than 0. Sensors publish at 0 and publish even when INVALID, so a failing sensor at 0 would mark a good CAN value invalid; 10 keeps the frame you configured in charge. Lua overrides sit at 200 and still win. Lower this to 0 only to let a local sensor take the channel back.
